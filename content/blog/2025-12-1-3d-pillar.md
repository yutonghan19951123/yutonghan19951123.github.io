I built a 3D interactive framework that resolves “spatial coincidence” in OD analysis by separating inflow and outflow with vertically extruded pillars, while preserving geographic truth and real-time performance at city scale.

## Background

OD analysis helps planners understand the “tidal” rhythm of commuting. It also helps teams diagnose root causes of congestion. The workflow often requires side-by-side comparison of inflow and outflow for each district. ￼

My project started from a common operational constraint. Practitioners manage districts, not raw GPS points. The system therefore aggregates many trips into a fixed set of AOIs. That step creates a structural problem. Both inflow and outflow land on the same (x, y) coordinates.

## The problem: spatial coincidence

Spatial coincidence is a topographic conflict. It happens when multiple scalar values occupy the same location on a map. In my case, the conflict was inflow vs. outflow at each AOI centroid. A 2D map collapses both values into a single point. No amount of transparency fixes the core ambiguity without distorting geography.

Design iterations I tested:

- **2D Circles**: The design caused heavy overlap at city scale. The design also introduced visual instability when offsets changed with zoom. ￼
- **2D Mirrored Pentagons** (two variants): The design anchored symbols well. The design still forced area-based judgment and mental transformation. The design increased cognitive load and reduced accuracy. ￼
- **Pseudo-3D Markers**: The design reduced values to categories. The design lost quantitative meaning and still overlapped. ￼
- **3D Cones**: The design looked attractive. The design relied on volume and shape integration. The design reduced comparison precision. ￼

## The core idea: pillars

I moved the problem out of the plane. I used vertical extrusion to separate coincident values without moving them on the map. The result was Pillars, a 3D encoding designed for stable comparison under density. ￼

The design follows three principles:

1. **Linear encoding**

   The system maps magnitude to height, not volume. Height supports more accurate comparison than area or volume. The decision was functional, not aesthetic. ￼

2. **Spatial stability**

   The system places origin and destination pillars with a fixed offset. The system avoids dynamic shifting. The design preserves the mental map during navigation. ￼

3. **Constrained viewpoint**

   The system uses a fixed 60° pitch. Users can pan and zoom. Users cannot freely orbit. The constraint keeps height comparison stable and reduces disorientation. ￼

## Interaction model: control complexity instead of drawing everything

3D pillars solve the node-level conflict. Dense N:N arcs create a new kind of clutter. I treated interaction as the main “clutter manager.” ￼

The system uses progressive disclosure. The system reveals structure step by step. The system reduces the analytic space from N:N to 1:N when the user needs detail. ￼

- **Coordinated views**

  The interface links the 3D map with an adaptive 2D panel. The 2D panel is a ranked bar view in overview. The 2D panel becomes a Sankey diagram in detail. Each view does what it is best at. ￼

- **Focus + context drill-down**

  A click on a pillar triggers a state transition. The system keeps the selected node prominent. The system fades unrelated nodes and flows. The design turns a messy N:N network into a readable 1:N pattern. ￼

   <figure class="blog-img-container">

- **Top-X density control**

  The interface lets users show Top 10/30/50/100 flows by volume. The control supports both “arteries” and “capillaries.” The control also protects performance. ￼

- **2D/3D toggle**

  The interface offers a perspective toggle for precise spatial lookup. The 3D view supports magnitude judgment. The 2D view restores exact footprints.

## Engineering: hybrid rendering for real-time performance

I used a hybrid architecture. MapLibre renders the basemap and static geometry. deck.gl renders high-frequency dynamic overlays. This split keeps interactions responsive. ￼

- **Static topology** (MapLibre)

  I optimized pillar gradients with a generated texture atlas. The system batches 386 pillar geometries in a single draw call. The approach used MapLibre’s fill-extrusion pattern and a Canvas-generated gradient sprite.

- **Dynamic flow** (deck.gl)

  I used instanced rendering for thousands of arcs. The system uploads geometry once. The system updates only per-instance attributes during interactions. The design supports stable transitions.

- **Declarative middleware**

  I injected React-style layer management into MapLibre. The middleware synchronizes UI state with GPU state. The approach reduces manual DOM coordination and layer bugs. ￼

## What I learned

This project taught me a simple lesson. Clarity is not only a visual problem. Clarity is also an interaction problem. A “better glyph” is not enough when users face N:N complexity. ￼

This project also shaped my research direction. I care about perceptual accuracy. I also care about industrial scalability. I want frameworks that survive contact with real city data and real product constraints.
